MASTER PROJECT TEMPLATE

BTTS PREDICTION ENGINE V1.0

TUJUAN PROJECT

Bangun sebuah Football BTTS Prediction Engine menggunakan Python CLI dengan database dan seluruh penyimpanan berbasis CSV.

Sistem hanya berfokus pada prediksi:

1. BTTS YES
2. BTTS NO

Jangan memasukkan pasar 1X2, Over/Under, Corners, atau Team Total sebagai target prediksi utama.

Sistem harus menghasilkan probabilitas BTTS YES dan BTTS NO berdasarkan data historis, statistik tim, performa home/away, H2H, dan model statistik.

Prinsip utama:

- Tidak boleh mengarang data.
- Tidak boleh mengisi statistik yang tidak tersedia dengan angka buatan.
- Semua prediksi harus bisa ditelusuri sumber datanya.
- Tidak boleh terjadi data leakage.
- Database wajib CSV, bukan SQLite.
- Implementasi dilakukan bertahap berdasarkan fase.
- Jangan mengubah data produksi atau konfigurasi project lain tanpa persetujuan.

1. JENIS MODEL

Gunakan beberapa model untuk dibandingkan secara historis.

A. Model Utama: Bivariate Poisson / Poisson Goals

Tujuan:
Menghitung estimasi gol tim tuan rumah dan tim tandang.

Fitur:

- Home attack strength
- Away attack strength
- Home defense strength
- Away defense strength
- League average goals
- Home advantage
- Recent scoring form
- Recent conceding form
- Home/away performance

Probabilitas BTTS YES dihitung dari distribusi gol kedua tim.

Untuk independent Poisson:

P(BTTS YES) = (1 - P(Home = 0)) × (1 - P(Away = 0))

P(BTTS NO) = 1 - P(BTTS YES)

Bivariate Poisson dapat diuji sebagai model alternatif untuk menangkap ketergantungan jumlah gol kedua tim. Jangan mengasumsikan model ini lebih baik sebelum diuji.

B. Model Pembanding: Logistic Regression

Target:

- 1 = BTTS YES
- 0 = BTTS NO

Fitur:

- Home scoring average
- Home conceding average
- Away scoring average
- Away conceding average
- Home BTTS percentage
- Away BTTS percentage
- Recent BTTS percentage
- H2H BTTS percentage
- League BTTS average
- Attack and defense strength

Gunakan probabilitas hasil prediksi, bukan hanya klasifikasi YES/NO.

C. Model Pembanding Tambahan

Uji jika data mencukupi:

- XGBoost
- LightGBM
- Random Forest

Model tambahan tidak boleh otomatis menjadi model utama.

D. Model Ensemble

Uji kombinasi model apabila hasil backtesting menunjukkan peningkatan yang konsisten.

Jangan melakukan ensemble hanya untuk meningkatkan kompleksitas sistem.

E. Evaluasi Model

Wajib menghitung:

- Log Loss
- Brier Score
- ROC-AUC
- Accuracy
- Precision
- Recall
- F1-Score
- Calibration
- Confusion Matrix

Evaluasi menggunakan chronological split dan walk-forward validation.

Pisahkan hasil berdasarkan liga dan musim.

Urutan mapping:

3. Normalisasi huruf besar/kecil.

- Pastikan home_team ditemukan.
- Pastikan away_team ditemukan.

- Pastikan liga sesuai.
- Pastikan pertandingan belum selesai.

7. ODDS DAN TRAINING MODEL

Ketentuan khusus:

Odds tidak boleh ditampilkan pada laporan prediksi akhir.

Untuk eksperimen training dan evaluasi historis, gunakan pendekatan berikut:

A. Historical Odds

- Simpan odds historis secara terpisah.
- Jangan menganggap odds 1X2 sebagai odds BTTS.
- Odds hanya boleh digunakan jika kolomnya benar-benar mewakili pasar BTTS.
- Pisahkan opening odds dan closing odds jika tersedia.

B. Simulated Odds / Probability

Buat eksperimen probabilitas simulasi untuk rentang:

- 1.50
- 1.60
- 1.70
- 1.80
- 1.90
- 1.95

Konversi odds desimal menjadi implied probability:

P = 1 / Odds

Kemudian lakukan evaluasi sensitivitas model terhadap rentang probabilitas tersebut.

PENTING:
Probabilitas simulasi bukan hasil pertandingan aktual dan tidak boleh dijadikan label training.

Label training tetap harus berasal dari hasil pertandingan nyata:

- BTTS YES = 1
- BTTS NO = 0

Model harus dilatih dari fitur pertandingan yang tersedia sebelum kick-off.

C. Live Odds

Jika ada API yang menyediakan pasar BTTS YES/NO:

- Uji ketersediaan pasar.
- Uji cakupan liga.
- Uji cakupan pertandingan.
- Periksa timestamp.
- Periksa apakah harga merupakan opening atau closing.
- Simpan sebagai data tambahan terpisah.
- Jangan wajibkan odds untuk menjalankan prediksi.

D. Output

Jangan tampilkan:

- Nilai odds.
- Nama bookmaker.
- Rekomendasi harga taruhan.

Tampilkan probabilitas BTTS saja.

8. DATA QUALITY DAN ANTI-LEAKAGE

Wajib diterapkan:

1. Statistik pertandingan hanya boleh menggunakan pertandingan sebelum waktu kick-off.
2. H2H tidak boleh memasukkan pertandingan yang berlangsung setelah tanggal prediksi.
3. Form tidak boleh menggunakan hasil pertandingan masa depan.
4. Jangan menghitung fitur dari seluruh dataset sebelum melakukan temporal split.
5. Semua fitur harus direkonstruksi sesuai tanggal prediksi historis.
6. Hindari data duplikat.
7. Periksa hasil pertandingan yang belum lengkap.
8. Jangan menganggap missing value sebagai nol.
9. Pisahkan data training, validation, dan testing berdasarkan waktu.
10. Simpan waktu pengambilan data dan sumbernya.

Jika data tidak cukup, sistem harus mengeluarkan DATA_INSUFFICIENT.

9. SARAN TAMBAHAN

Tambahkan fitur berikut jika data mencukupi:

A. Recent Form Weighting

Berikan bobot lebih besar pada pertandingan terbaru.

Uji beberapa periode dan decay parameter melalui walk-forward validation.

B. Attack vs Defense Matchup

Analisis:

- Kekuatan serangan home melawan pertahanan away.
- Kekuatan serangan away melawan pertahanan home.

C. Scoring Consistency

Ukur konsistensi kedua tim dalam mencetak gol.

D. Defensive Vulnerability

Ukur frekuensi kebobolan minimal satu gol.

E. Sample Size Reliability

Statistik 3 pertandingan tidak boleh diperlakukan sama kuat dengan statistik 20 pertandingan.

Gunakan minimum sample dan shrinkage terhadap rata-rata liga.

F. League-Specific Calibration

Periksa kalibrasi probabilitas per liga.

G. Probability Confidence

Pisahkan:

- Predicted Probability = probabilitas model.
- Confidence Level = tingkat keandalan berdasarkan sampel, kualitas data, dan kalibrasi.

Jangan menyamakan confidence dengan probabilitas BTTS.

H. Model Comparison

Bandingkan model pada test set yang sama.

Model terbaik dipilih berdasarkan performa probabilistik, bukan accuracy saja.
